# 苹果五姿态手眼一致性测试

目的：验证同一颗固定苹果经过 `camera_color_optical_frame -> Link6 -> base_link` 换算后，在 `base_link` 下是否保持固定。整个测试不运行 MoveIt、不接近苹果、不闭合夹爪。

## 测试前提

- 桌面只保留一颗苹果，并固定住，测试期间绝对不能移动。
- 夹爪保持打开。
- 机械臂只通过示教器低速移动。
- RealSense 必须启用对齐深度和同步。
- `base_link -> camera_color_optical_frame` 必须能持续查询。
- 苹果在五个姿态下都应完整可见，不能被夹爪遮挡或贴近图像边缘。

苹果不是理想标定靶。可见深度落在苹果表面，相机换方向时表面点会改变。因此新版节点发布：

- `/apple_pick_v2/apple_surface`：蓝色小点，原始可见表面点，仅供诊断。
- `/apple_pick_v2/apple_center`：红色球心，根据 YOLO 分割尺寸、深度和相机内参估算的苹果中心，用于一致性统计。

红色中心仍是假设苹果近似球形的估计。测试通过后，最好再用 AprilTag/ArUco 做一次更严格验证。

## 终端 1：启动苹果中心定位

先确保机械臂驱动、`robot_state_publisher`、RealSense 和手眼静态 TF 已运行。然后：

```bash
source /opt/ros/jazzy/setup.bash
source $ROS_WS/install/setup.bash
"$APPLE_YOLO_PYTHON" "$APPLE_CATCH_ROOT/apple_pick_v2/apple_center_localizer_v2.py"
```

此节点没有机械臂、MoveIt 或 RS485 发布接口。

## RViz 设置

Fixed Frame 设为 `base_link`，添加：

- `MarkerArray`：`/apple_pick_v2/hand_eye_markers`
- `Pose`：`/apple_pick_v2/apple_center`
- `Pose`：`/apple_pick_v2/apple_surface`
- `TF`
- 相机 Image（可选）

红色半透明球应覆盖苹果主体，蓝色点应落在朝向相机的苹果表面。若红球直径明显错误、跳到背景或苹果被截断，不要采样。

诊断信息可查看：

```bash
ros2 topic echo /apple_pick_v2/apple_diagnostics
```

关注 `radius_m`、`sync_error_ms`、`valid_depth_pixels` 和两套 XYZ。

## 终端 2：运行五姿态记录器

```bash
source /opt/ros/jazzy/setup.bash
source $ROS_WS/install/setup.bash
$APPLE_YOLO_PYTHON $APPLE_CATCH_ROOT/apple_pick_v2/hand_eye_consistency_test.py
```

记录器会依次提示：鸟瞰位、左侧观察、右侧观察、前侧观察、腕部旋转观察。每次：

1. 用示教器低速移动到安全姿态。
2. 苹果保持完整可见，机械臂完全停止。
3. 等待图像和关节状态稳定 1–2 秒。
4. 按 Enter，程序自动读取 10 个新样本并计算均值、标准差和异常值。

不要在采样过程中移动机械臂。五个姿态必须包含明显腕部转角，不能只是小范围平移。

## 自动判断

- 最大姿态间距离不超过 10 mm：`PASS`，可以进入只规划阶段。
- 10–20 mm：`WARN`，复测并检查苹果中心估计。
- 超过 20 mm：`FAIL`，停止 IK 和抓取。

每个姿态还会输出轴向标准差和最大单姿态抖动：

- 同一姿态抖动大：先查深度、光照、YOLO 掩膜、遮挡和同步。
- 同一姿态稳定，但换腕部角度后漂移大：先查手眼旋转方向、外参方向和相机 TF 父子关系。
- 五姿态彼此一致但整体位置有固定误差：一致性链路可能正常，但苹果球心模型或绝对手眼平移仍可能有偏差；一致性测试不能替代已知尺寸靶标的绝对精度验证。

结果自动保存在：

```text
$APPLE_CATCH_ROOT/apple_pick_v2/results/hand_eye_日期_时间/
```

其中 `samples.csv` 保存每帧 XYZ 与关节角，`summary.json` 保存五姿态统计和最终判定。
