# 单苹果连续换位抓取设计

日期：2026-08-11

## 1. 目标

在保留现有单轮真机抓取流程和安全门禁的前提下，增加一个常驻连续模式。相机视野内始终只允许一颗苹果。每轮由程序自动完成：

```text
固定 SCAN
→ 稳定识别唯一苹果
→ 完整路径预检
→ PREGRASP
→ VERIFY
→ GRASP
→ 闭合夹爪
→ LIFT
→ 原抓取位置 RELEASE
→ 打开夹爪
→ PREGRASP
→ 固定 SCAN
```

程序回到 SCAN 后不退出。操作者把同一颗苹果移动到新位置，退出机械臂工作区；程序确认新位置已经变化且稳定后，自动开始下一轮。默认持续运行到 `Ctrl+C`，也可以限制最大轮数。

本功能不扩展为多苹果选择、自动放置到其他区域、树上抓取或基于点云的人体检测。

## 2. 已确认约束

- 只使用现有固定 SCAN 鸟瞰位。
- 视野内只放一颗苹果。
- 继续使用当前 `apple_center`、视觉 XY 尺度校正、TCP、候选姿态、MoveIt 路径预检、RS485 夹爪和原位放回参数。
- 每轮都把苹果放回本轮原抓取位置，不去独立放置点。
- 不要求每轮按 Enter；检测到新位置稳定后自动开始。
- 运动前的识别或规划失败可以自动重试。
- 真机一旦开始本轮运动，任何失败都必须停止后续循环，不自动补救运动。
- 现有单轮命令和行为必须保持兼容。

## 3. 选择的架构

采用常驻状态机，而不是 Shell 循环重启 Python，也不是在现有千行 `main()` 外简单套无限 `while`。

现有单轮流程被整理为可复用的单轮执行单元；它继续负责目标生成、候选筛选、完整规划、轨迹执行、夹爪控制、原位放回和回 SCAN。新的连续控制器只负责轮次、稳定门禁、重试、状态转换和会话日志。ROS 2 节点、MoveIt 接口和夹爪通信在进程启动时建立一次，轮次之间不重新初始化。

计划边界：

- `SingleRoundRunner`：执行一个已经冻结目标的完整抓取与原位放回流程。
- `ContinuousGraspController`：等待目标、决定是否允许开始、调用单轮执行器并维护循环状态。
- `AppleStabilityGate`：只处理苹果位置变化、稳定窗口和安全倒计时，不发送运动命令。
- 现有 `single_apple_full_grasp.py` 单轮 CLI：行为保持不变。
- 新连续 CLI：显式要求连续真机授权，不因 YAML 配置自动启动机械臂。

## 4. 状态机

```text
START
  → ENSURE_SCAN
  → WAIT_NEW_APPLE
  → STABILITY_CHECK
  → SAFETY_COUNTDOWN
  → PLAN_ROUND
  → EXECUTE_PICK
  → EXECUTE_LIFT
  → EXECUTE_RETURN
  → ENSURE_SCAN
  → ROUND_COMPLETE
  → WAIT_NEW_APPLE
```

终止状态：

- `COMPLETE`：达到 `max_rounds`。
- `STOPPED_BY_OPERATOR`：收到 `Ctrl+C`。
- `FAULT_LATCHED`：真机开始运动后发生任何异常。

### 4.1 首轮门禁

启动后没有“上一轮放回位置”。机械臂确认位于 SCAN、夹爪确认已发送打开命令后，只要唯一苹果坐标连续稳定达到配置时间，并通过现有视觉质量门禁和安全倒计时，即可自动开始第一轮。

### 4.2 后续轮次门禁

每轮完成原位释放并返回 SCAN 后，记录该轮放回目标中心。下一轮候选必须满足：

1. 当前中心与上一轮放回中心的三维距离至少为 `min_position_change_m`；
2. 中心在稳定窗口内的 XYZ 峰峰值通过现有 `max_axis_span_m` 门禁；
3. 连续稳定时间达到 `stable_time_s`；
4. 随后的 `safety_countdown_s` 内目标仍然有效且稳定；
5. 任一条件被破坏时清空计时，重新等待。

苹果可以在搬动时暂时消失；重新出现后按同样规则重新建立稳定窗口。只有内部 ROI 误拒绝等已经由定位节点处理的问题继续沿用现有诊断，不在连续控制器中修改 YOLO 阈值或图像算法。

## 5. 配置和命令行

在 `single_apple_full_grasp.yaml` 增加：

```yaml
continuous:
  max_rounds: 0
  min_position_change_m: 0.030
  stable_time_s: 2.0
  safety_countdown_s: 3.0
  retry_delay_s: 2.0
  max_pre_motion_retries: 3
```

定义：

- `max_rounds: 0` 表示无限运行；正整数表示成功完成该轮数后停止。
- `min_position_change_m` 使用经过现有视觉 XY 校正后的 `base_link` 苹果中心计算。
- `max_pre_motion_retries` 只针对同一个稳定目标的识别快照或规划失败。超过次数后放弃该位置，继续等待苹果再次改变位置，不执行运动。

连续模式必须显式提供：

```text
--continuous --execute --operator-confirmed
```

`--max-rounds N` 可临时覆盖 YAML；未提供时使用 YAML。`--continuous` 与 `--verify-only`、`--preflight-only`、旧的单轮人工确认组合互斥。连续模式等价于每轮启用已经验证的自动 VERIFY→GRASP 和 LIFT→原位放回→SCAN，但不改变旧 `--fully-autonomous` 的单轮语义。

## 6. 数据流

```text
/apple_pick_v2/apple_center + /apple_pick_v2/apple_diagnostics
  → AppleStabilityGate
  → 冻结本轮稳定中心和半径
  → 视觉 XY 校正及有效范围门禁
  → SingleRoundRunner 完整规划
  → 规划全部通过后才允许真机运动
  → 抓取、LIFT、原位放回、SCAN
  → 保存本轮结果和上一轮放回中心
```

同一轮从稳定门禁到规划使用同一个冻结目标。开始运动前如果实时目标相对冻结目标发生超限变化，本轮取消并回到等待状态。开始运动后不再因 YOLO 暂时看不到苹果而中断已经通过预检的路径，也不把“苹果消失”当作夹持成功证据。

## 7. 失败处理

### 7.1 尚未运动

- 没有苹果、样本不足、TF 暂时缺失：保持 SCAN，按 `retry_delay_s` 重试。
- 苹果位置不稳定：重置稳定窗口，不规划。
- IK、碰撞或完整路径预检失败：不执行轨迹；对同一个稳定目标最多重试 `max_pre_motion_retries` 次。
- 同一目标超过重试次数：标记该位置为拒绝，等待目标位置再次变化至少 `min_position_change_m`。

### 7.2 已开始运动

以下任一情况进入 `FAULT_LATCHED`，记录日志并停止循环：

- 轨迹执行失败或超时；
- TCP 到位误差超限；
- 夹爪命令失败；
- LIFT、RELEASE、撤离或回 SCAN 失败；
- MoveIt 接口或关节状态在执行阶段失效。

故障后不自动重新规划、不自动打开夹爪、不盲目返回 SCAN。程序保留当前夹爪状态和机械臂状态，提示操作者使用示教器或急停处理。

`Ctrl+C` 在轮次之间用于正常退出；真机运动中的紧急停止仍以机械臂急停为准，不能把终端信号当作人员防护装置。

## 8. 日志

保留现有每轮 JSON，并增加一次连续会话的汇总 JSON：

- 会话开始/结束时间；
- 配置快照和命令行覆盖；
- 每轮原始中心、校正中心、上一轮距离、稳定跨度；
- 每轮候选姿态、规划结果和执行结果；
- 每轮放回中心、完成时间和日志路径；
- 总成功轮数、预运动拒绝次数、最终停止原因；
- `FAULT_LATCHED` 时的状态、阶段和原始异常。

终端只输出状态变化和简洁进度，不逐帧刷屏。

## 9. Git 保护

实施前先只读检查当前工作区差异，选择性保存与当前成功抓取有关的已有修改，建立“连续抓取前基线”提交。不得把仓库内其他无关未跟踪文件混入提交。

提交顺序：

1. 本设计文档；
2. 当前成功单轮源码基线；
3. 状态机与自动化测试实现；
4. plan-only/单轮真机回测修正；
5. 两轮真机连续验证和文档更新。

每个阶段都记录提交哈希。现有单轮入口作为回退路径保留；连续模式出现问题时可以直接运行原单轮命令，不依赖新状态机。

## 10. 验证顺序和通过标准

### 10.1 无真机运动

1. 用合成坐标序列验证首轮稳定、原位抑制、换位、抖动重置、暂时消失、最大轮数和 `Ctrl+C` 状态转换。
2. 验证命令行覆盖 YAML，互斥参数会在创建运动前拒绝。
3. 回归现有单轮参数解析和主要纯函数。
4. 使用实时视觉和 MoveIt 做 plan-only，不控制夹爪、不发送轨迹。

### 10.2 真机回测

1. `max_rounds=1`：验证连续控制器执行结果与现有成功单轮流程一致，并完成原位放回和返回 SCAN。
2. `max_rounds=2`：第一轮结束后保持原位，确认程序不会立刻重复抓取；操作者移动苹果并退出工作区后，确认稳定倒计时自动触发第二轮。
3. 第二轮必须完成抓取、LIFT、原位放回和回 SCAN，然后因达到轮数正常停止。
4. 检查两份单轮日志和一份会话日志完整存在。

YAML 默认的 `max_rounds: 0` 表示无限循环，因此一轮和两轮验证必须分别显式传入 `--max-rounds 1` 和 `--max-rounds 2`。只有两轮真机测试全部通过，后续测试才允许省略命令行覆盖并使用 YAML 的无限循环值。测试期间机械臂保持低速，急停可用，视野内只允许一颗苹果。

## 11. 成功标准

- 整套 ROS/MoveIt/视觉系统只启动一次；连续控制进程也只启动一次。
- 第一轮可由稳定苹果自动触发。
- 原位放回后不会立即重复抓取相同位置。
- 苹果移动超过阈值并稳定后，无需 Enter 自动开始下一轮。
- 每轮继续使用已验证的视觉校正、规划、夹爪和原位放回逻辑。
- 运动前失败不会导致机械臂动作；运动后失败不会自动继续下一轮。
- `max_rounds` 和 `Ctrl+C` 均能结束会话。
- 现有单轮启动方式不受影响，并可作为可靠回退入口。
