# 机械臂抓取苹果过程记录

- 记录日期：2026-08-31
- 当前阶段：需求与系统流程梳理
- 应用场景：农田环境中的水果抓取

## 目标

让机械臂在农田环境中识别并抓取苹果。场景中可能同时存在多个水果，因此系统需要确定目标苹果，而不仅是识别“画面中有苹果”。

## 抓取流程

1. **识别苹果**
   - 使用机械臂搭载的摄像头采集环境图像。
   - 从可能存在多个水果的画面中识别苹果。

2. **确定三维位置**
   - 获取目标苹果在三维空间中的位置。
   - 定位结果需要达到机械臂可执行抓取的精度。

3. **规划并执行抓取**
   - 系统根据苹果的三维位置控制机械臂接近目标。
   - 调整末端执行器姿态并完成抓取。

4. **保证系统稳定运行**
   - 机械臂整体系统需要在农机载体上稳定运行。
   - 运行中涉及两类变化：机械臂在空间中的运动，以及载体颠簸引起的机械结构与观测变化。

## 系统链路

`摄像头采集 → 苹果识别 → 目标选择 → 三维定位 → 运动规划 → 机械臂抓取 → 抓取结果确认`

## 待确认问题

1. 多个水果同时出现时，目标苹果如何选择：按成熟度、距离、抓取难度，还是预设顺序？
2. 苹果的三维位置能否仅依靠桌面上的计算机完成估计？需要明确摄像头类型、标定方式和深度获取方案。
3. 机械臂的控制通信是否采用现有通信协议？需要确认协议类型、控制频率、延迟和丢包容忍度。
4. 农机载体颠簸时，摄像头与机械臂是否刚性连接？是否需要 IMU、视觉补偿或实时重定位？
5. 抓取成功如何判定：视觉确认、夹爪力反馈、位置反馈，还是多种信号融合？

## 建议的下一步实验

先在静止平台、单个苹果、固定光照条件下验证最小闭环：

1. 摄像头稳定识别单个苹果。
2. 将苹果中心转换为机械臂坐标系中的三维坐标。
3. 机械臂移动到预抓取点。
4. 执行抓取并判断是否成功。
5. 记录定位误差、抓取成功率和单次耗时。

完成静态单目标闭环后，再逐步加入多个苹果、枝叶遮挡、自然光变化和农机颠簸，便于准确定位每一阶段的问题。

## 2026-08-31 执行方案草案

> 以下内容根据手写方案整理。含义不清的地方按假设记录，不作为已经确定的事实。

### 当前设想

1. 使用 YOLO 识别苹果，识别范围尚未确定为“仅苹果”还是“多种水果”。
2. 使用视觉设备同时获得颜色信息和位置/深度信息；当前笔记提到双目或深度相机，但具体硬件组合尚未确定。
3. 给机械臂设置一个固定的初始位置，抓取时进行三次微调。

### 当前观察到的问题

1. 桌面上只有一个无遮挡苹果时，可以正常抓取。
2. 苹果约有 60% 被遮挡时，不能正常抓取。
3. 同时出现两个苹果时，系统无法完成抓取；当前推测是系统不知道应选择哪一个。

### 当前技术疑问

1. 是否能依靠热成像或光谱技术识别水果，而不是使用 AI？
2. 如何用视觉设备可靠地确定苹果的三维位置？

## 第一性原理审视

### 1. 先定义真正的问题

最终任务不是“检测图片里有没有苹果”，而是：

> 在给定时间内，从多个候选苹果中选择一个当前可抓取的目标，估计可执行的抓取位姿，规划无碰撞运动，完成低损伤抓取，并确认结果。

因此，完整系统至少需要六种能力：

`感知 → 三维定位 → 目标选择 → 抓取位姿生成 → 运动控制 → 结果确认`

当前方案主要覆盖了“感知”的一部分，并初步连接了运动控制。其余环节如果没有明确规则，单目标演示成功也不能证明系统具有通用抓取能力。

### 2. YOLO 可以保留，但必须明确其边界

YOLO 适合解决“图像中的苹果在哪里”这一二维检测问题，但它本身不负责：

- 判断多个苹果中应该先抓哪一个；
- 给出可直接执行的三维抓取位姿；
- 判断夹爪从哪个方向接近；
- 判断枝叶、桌面或其他苹果是否挡住运动路径；
- 判断抓取是否成功。

第一版应只识别苹果，不要同时扩大到所有水果。不同水果的形状、成熟度特征和抓取约束不同，过早扩大类别会增加数据和控制变量，却不能验证核心闭环。

### 3. 热成像、光谱和 AI 不是互斥选项

热成像、RGB、深度和光谱是传感方式；AI 或传统算法是解释传感数据的方法。换用热成像或光谱并不会自动消除算法需求。

- **RGB**：成本低，适合苹果检测和颜色/成熟度初步判断，但受光照和遮挡影响。
- **深度或双目**：提供几何信息，适合计算三维位置，是桌面抓取闭环的直接需求。
- **热成像**：只有目标与背景存在稳定温差时才明显有利；它通常不是苹果几何定位的首选。
- **多光谱/高光谱**：可能帮助判断成熟度、病害或内部特征，但成本、标定、光照控制和数据处理复杂度更高，也不能替代三维几何感知。

结论：当前最直接的基线是 **RGB-D 相机或已标定的双目相机 + 苹果检测/分割**。只有在 RGB 无法达到明确指标时，再用实验判断是否增加光谱传感器。

### 4. “识别位置”必须变成完整坐标链

相机看到的像素不能直接发送给机械臂。至少需要完成：

1. 相机内参标定；
2. RGB 与深度对齐；
3. 从苹果区域取得稳定深度，而不是盲取检测框中心的单个像素；
4. 将相机坐标转换到机械臂基坐标；
5. 完成相机与机械臂的外参/手眼标定；
6. 根据苹果表面、半径和夹爪结构生成预抓取点、抓取点及接近方向。

若只输出苹果中心的 `(x, y, z)`，机械臂仍不知道末端应以什么姿态接近，也无法判断目标是否实际可抓。

### 5. 两个苹果时失败，本质是缺少决策规则

检测模型发现两个苹果不是异常，而是正常输入。系统必须为每个候选目标保存独立实例，并使用确定性的评分规则选择一个，例如：

`目标得分 = 可见面积 + 深度可靠度 + 可达性 + 周围净空 - 运动距离 - 遮挡风险`

第一版可以更简单：只在满足深度有效、位于机械臂工作空间且周围无遮挡的苹果中，选择距离预抓取位姿最近的一个。完成当前目标后重新检测，再选择下一个。

### 6. 遮挡失败必须拆开诊断

“遮挡 60% 后不能抓”无法直接指导修改，因为失败可能发生在不同环节：

- 没有检测到苹果；
- 检测到了，但深度数据不足或取到了遮挡物；
- 三维位置正确，但抓取点被遮挡；
- 抓取点可用，但路径发生碰撞；
- 已接触苹果，但夹爪没有稳定夹住。

每次实验必须记录失败停在哪一层。遮挡比例也应通过可复现的遮挡板或分级样本定义，而不是只靠目测写“60%”。

### 7. “固定位置 + 三次微调”不等于闭环控制

如果三次微调只是预先写死的动作，它仍然是开环脚本，只能适应固定桌面和固定苹果位置。真正的闭环应是：

1. 观察并估计目标位姿；
2. 移动一段距离；
3. 重新观察目标；
4. 计算末端与目标之间的剩余误差；
5. 根据误差继续调整，达到阈值后抓取。

停止条件应由误差阈值、最大迭代次数和安全距离共同决定，而不是固定为三次。三次可以作为安全上限，但不能作为控制逻辑本身。

## 建议的最小可验证架构

```text
RGB-D 图像
   ↓
苹果实例检测/分割
   ↓
每个苹果的 3D 候选位姿与置信度
   ↓
可达性、遮挡和净空过滤
   ↓
确定性目标评分与选择
   ↓
预抓取位姿 → 视觉复测 → 误差修正
   ↓
夹爪闭合 → 抬升 → 成功确认
```

每一层都应输出中间结果和失败原因。这样系统失败时，能够判断应该改数据、标定、目标规则、路径规划还是夹爪，而不是笼统归因于 YOLO。

## 分阶段执行方案

### 阶段 A：验证坐标闭环

- 条件：固定相机、固定机械臂、无遮挡的单个仿真苹果或苹果模型。
- 目标：不抓取，只让末端准确到达预抓取点。
- 指标：三维定位误差、末端到位误差、重复性。
- 通过门槛：误差持续小于夹爪允许的抓取容差，而不是偶然成功一次。

### 阶段 B：验证单目标抓取

- 增加夹爪闭合、抬升和成功确认。
- 在机械臂工作空间内设置多个离散位置，每个位置重复试验。
- 记录成功率、单次耗时、苹果滑落和损伤情况。

### 阶段 C：验证多目标决策

- 同时放置两个或多个无遮挡苹果。
- 为目标选择定义唯一且可复现的规则。
- 验证系统每次都能说明“选择了哪个苹果、为什么选择它”。

### 阶段 D：验证遮挡和碰撞

- 将“未遮挡、轻度遮挡、中度遮挡、不可抓取”定义成可复现实验组。
- 分别记录检测、深度、可达性、规划和夹取阶段的结果。
- 对不可安全抓取的苹果，正确行为应是跳过或重新观察，而不是强行执行。

### 阶段 E：再引入农田变量

- 逐项增加自然光、枝叶、苹果姿态、风和平台振动。
- 每次只增加一个主要变量，以便知道性能下降来自哪里。
- 静态闭环未通过前，不应直接投入农机移动场景；否则视觉、标定和振动误差会混在一起，无法诊断。

## 必须补齐的验收指标

| 层级 | 最小指标 |
| --- | --- |
| 检测 | 苹果召回率、误检率、遮挡等级下的召回率 |
| 定位 | 相机坐标误差、转换到机械臂坐标后的误差 |
| 决策 | 多目标选择正确率、无可抓目标时的拒绝率 |
| 控制 | 末端到位误差、微调次数、规划失败率 |
| 抓取 | 抓取并抬升成功率、滑落率、损伤率 |
| 系统 | 单次周期时间、连续运行次数、失败原因分布 |

## 当前结论

- **可以继续使用**：YOLO、深度相机/双目、固定桌面上的最小实验。
- **需要立即补齐**：坐标标定链、抓取位姿、目标选择策略、反馈闭环、成功判定和分层日志。
- **暂缓增加**：全水果识别、热成像/光谱、农机振动补偿。它们不是当前最小闭环的首要瓶颈。
- **应当修改**：“固定位置后微调三次”改为“每次移动后重新观测，根据误差收敛；三次仅作为最大重试次数之一”。

## 2026-08-31 新增实验事实与架构修正

### 已观察事实

1. 在无遮挡、静态场景下，机械臂已经可以完成苹果抓取。
2. 苹果受到遮挡时，系统不能正常完成抓取。
3. 每次抓取完成后，机械臂必须返回固定鸟瞰观察点，才能重新判断场景中是否还有苹果。

### 对现状的判断

这说明当前系统已经打通了特定条件下的基本坐标与抓取链路，但整体仍属于：

`返回固定观察点 → 拍摄一次 → 识别苹果 → 抓取一次 → 再返回固定观察点`

固定鸟瞰点同时承担全局感知和任务重置，因此机械臂一旦离开这个位置，系统就失去了可靠的全局场景信息。这不是机械臂运动本身的问题，而是相机视角和感知状态管理的架构限制。

### 遮挡问题应分为两类

1. **可见但识别失败**：仍能看到足够苹果表面，但检测模型、深度取值或中心估计失败。可以通过遮挡数据训练、实例分割、可见轮廓拟合和稳健深度估计改善。
2. **物理上不可抓**：苹果虽然能被识别，但夹爪接近方向或运动路径被其他苹果、枝叶或障碍物挡住。此时不能靠提高 YOLO 准确率解决，正确策略是跳过、换视角或先抓走遮挡它的目标。

因此，系统输出不能只有“检测到苹果”，还需要输出：

```text
检测状态：是否看见
定位状态：三维位置是否可靠
抓取状态：是否存在安全接近方向
决策结果：抓取 / 换视角 / 暂时跳过
```

### 鸟瞰点问题的三种方案

#### 方案 A：暂时保留每次回鸟瞰点

- 优点：不改变硬件，标定关系稳定，最容易验证。
- 缺点：路径长、速度慢、重复运动多，在移动农机上固定鸟瞰关系可能失效。
- 定位：适合作为当前可靠基线，不适合作为最终效率方案。

#### 方案 B：固定全局相机 + 机械臂近距离相机

- 固定相机持续观察全部苹果，维护全局候选目标列表。
- 机械臂上的相机只负责接近目标后的局部复测和误差修正。
- 抓取后由固定相机更新剩余苹果，不要求机械臂回到唯一鸟瞰点。
- 这是兼顾全局视野、抓取精度和效率的推荐架构，但需要完成两套相机到机械臂坐标系的标定与融合。

#### 方案 C：只使用机械臂相机，但动态选择观察位姿

- 不再固定回到同一个鸟瞰点，而是从若干安全观察位姿中选择能看清剩余区域的最近位置。
- 遇到遮挡时主动换视角，再更新目标三维位置。
- 硬件增加较少，但观察位姿规划、遮挡判断和状态维护的软件复杂度更高。

### 当前推荐的实施顺序

1. **保留鸟瞰点作为基线**，先记录每次完整循环的时间，以及返回鸟瞰点占用的时间比例。
2. 给每个候选苹果计算可见程度、深度有效率和抓取净空，优先抓取最无遮挡、最容易接近的苹果。
3. 每抓走一个苹果后重新观察，因为场景和遮挡关系已经改变；原来的坐标不能直接长期复用。
4. 对遮挡目标增加“跳过”或“换视角”状态，不允许在定位不可靠时直接执行抓取。
5. 如果返回鸟瞰点成为主要效率瓶颈，再实施“固定全局相机 + 机械臂局部相机”，而不是先改检测模型。

### 下一轮最有价值的测试

设置两个苹果，让前方苹果部分遮挡后方苹果：

1. 鸟瞰识别两个候选目标；
2. 系统选择可见度更高、路径更安全的前方苹果；
3. 抓走前方苹果；
4. 返回鸟瞰点或由固定全局相机重新观察；
5. 检查后方苹果是否从“被遮挡/暂不可抓”变成“可抓”；
6. 记录每个阶段的检测、深度、选择理由、抓取结果和耗时。

这个实验可以同时验证遮挡处理、目标排序和重新观察机制，比单纯继续提高 YOLO 置信度更接近真实问题。

## 2026-08-31 方案第二次第一性原理审视

### 新增设想

将工作过程简化为：农机载着机械臂到达目标区域后停车，等待系统稳定，再由机械臂完成观察和抓取。希望通过停车消除载体运动造成的环境与结构变化，使抓取过程接近静态执行。

### 对该设想的客观判断

这是合理的第一阶段范围收缩，但只能消除“抓取期间底盘持续运动”这个变量，不能自动消除以下变量：

- 停车后的残余振动和结构回弹；
- 每次停车位置、角度和机械臂基座姿态不同；
- 苹果和枝叶受风摆动；
- 阳光、阴影和曝光变化；
- 苹果遮挡、重叠和抓取路径受阻；
- 抓走一个苹果后场景发生变化。

正确表述应是：

> 第一阶段只研究“载体停车并稳定后，在局部相对坐标系中抓取可见苹果”，暂不研究行驶过程中抓取。

这里不必让机械臂知道车辆在果园中的绝对位置。每次停车后重新观察苹果，并在相机—机械臂的局部坐标系内定位即可。前提是相机与机械臂之间的刚性安装关系没有变化。

### 深度学习在系统中的正确位置

- YOLO 或实例分割模型负责回答“哪些图像区域是苹果”。
- RGB-D/双目和相机标定负责回答“苹果相对相机的三维位置”。
- 手眼标定和坐标转换负责回答“这个位置在机械臂坐标系中在哪里”。
- 规则或规划算法负责回答“抓哪一个、能不能安全接近、从哪里接近”。
- 视觉反馈负责回答“移动后还差多少、是否需要修正”。

因此，不应把全部问题统称为“深度学习问题”。尤其是度量三维位置，优先使用经过标定的几何测量；若只有普通单目 RGB，相对深度可以估计，但通常不应直接作为高精度抓取的唯一度量来源。

## 对原步骤的逐项修正

### 原步骤 1：用 YOLO 识别苹果或水果

**判断：方向可用，但范围过宽。**

第一版只做苹果。模型输出应是每个苹果的独立实例，而不是只有“画面中存在苹果”。如果遮挡是主要问题，实例分割比单纯检测框更有利于估计可见区域和稳定深度。

### 原步骤 2：用镜头识别颜色和位置

**判断：描述不完整。**

相机不是一个负责颜色、另一个自然负责位置。必须明确硬件和坐标链：

`RGB/深度数据 → 苹果区域 → 深度过滤 → 相机三维坐标 → 手眼标定 → 机械臂坐标 → 抓取位姿`

当前静态抓取已经成功，说明这条链在特定条件下大概率基本可用；下一步不应立即更换相机，而应先测量它在多位置、遮挡和停车振动后的误差。

### 原步骤 3：固定机械臂位置，抓取时微调三次

**判断：固定观察点可以保留，固定三次微调逻辑应删除。**

- 鸟瞰点是当前获得全局视野的必要观察位姿，可以作为第一版流程的一部分。
- 微调次数不应预先固定；每次微调后必须重新测量误差。
- 控制逻辑应为“误差达到阈值则抓取；否则继续修正；超过最大次数则安全退出”。

### 原步骤 4：农机停车后稳定抓取

**判断：适合作为 MVP 边界，但必须增加稳定判据。**

不能只凭“车辆已经停车”判断可以抓取。应设立：

- 停车完成信号；
- 可测量或经实验确定的稳定等待时间；
- 图像连续若干帧位移低于阈值；
- 深度和目标坐标连续若干帧波动低于抓取容差。

只有这些条件满足后，系统才能进入抓取状态。

## 重构后的执行流程

```text
1. 农机停车
2. 等待振动与图像稳定
3. 机械臂回到鸟瞰观察点
4. 获取多帧 RGB-D 数据
5. 检测/分割所有苹果实例
6. 为每个苹果计算三维位置、可见度、深度质量和可达性
7. 过滤定位不可靠或当前不可安全抓取的目标
8. 按确定性规则选择最容易抓取的苹果
9. 移动到预抓取点
10. 重新观察并根据误差闭环修正
11. 误差达标后执行抓取、抬升并确认成功
12. 返回鸟瞰点，重新观察改变后的场景
13. 无可抓目标则结束当前停车点任务
```

### 推荐的第一版目标选择规则

不需要再训练一个 AI 来决定抓哪个。第一版直接使用可解释规则：

1. 深度必须有效；
2. 目标必须位于机械臂工作空间；
3. 夹爪必须有安全接近方向；
4. 在符合以上条件的目标中，优先选择可见面积最大、遮挡最少的苹果；
5. 若仍有多个候选，选择运动距离最短的一个。

## 重构后的测试计划

### Gate 0：冻结第一版范围

- 只抓苹果；
- 农机停车后抓取；
- 保留固定鸟瞰点；
- 允许系统跳过不可抓目标；
- 暂不承诺行驶中抓取、全水果识别或严重遮挡抓取。

### Gate 1：静态定位重复性

- 苹果固定不动，连续采集多帧三维坐标。
- 苹果放在工作空间多个已知位置，重复测量。
- 通过条件：定位误差和抖动小于夹爪与苹果之间允许的机械容差。

### Gate 2：静态单苹果抓取

- 在多个位置重复抓取无遮挡苹果。
- 分别记录检测、定位、到位、夹取和抬升结果。
- 通过条件：达到预先定义的连续成功率，并且失败能定位到具体阶段。

### Gate 3：多苹果目标选择

- 同时放置两个无遮挡苹果。
- 验证系统按同一规则稳定选择目标，并在抓取后重新观察剩余苹果。
- 通过条件：每次选择都有确定原因，不再出现“不知道抓哪个”。

### Gate 4：分离遮挡测试

- 视觉遮挡：只挡相机视线，不挡夹爪路径，测试识别与三维定位。
- 物理遮挡：相机能看见苹果，但障碍物挡住夹爪路径，测试可达性判断与安全拒绝。
- 通过条件：系统能区分“看不准”和“进不去”，而不是统一报告抓取失败。

### Gate 5：停车后稳定性

- 让农机多次移动、停车并等待稳定，每次重新执行同一目标测试。
- 测量停车后图像稳定时间、定位漂移和抓取成功率。
- 通过条件：不同停车轮次中局部定位与抓取性能仍满足机械容差。

### Gate 6：效率优化

- 统计鸟瞰返回时间、感知时间、规划时间和抓取时间。
- 只有当返回鸟瞰点被数据证明是主要瓶颈时，再考虑增加固定全局相机或动态观察位姿。

## 当前最重要的风险排序

1. **坐标和深度在遮挡或停车振动后不稳定。**
2. **没有可抓取性判断，把识别成功误认为可以执行。**
3. **缺少多目标选择规则。**
4. **固定三次微调不能保证误差收敛。**
5. **过早研究热成像、光谱或全水果类别，分散验证核心闭环的资源。**

## 第二次审视结论

“停车后再抓”是正确的 MVP 决策，因为它减少了一个高影响变量；但它不是稳定性的证明。你们接下来不需要先扩充技术，而需要把已经能工作的静态抓取变成可重复、可测量、可拒绝危险动作的系统。第一阶段真正的完成标准不是“成功抓过一次”，而是系统在多个位置、多次停车和明确遮挡条件下，能够稳定抓取可抓目标，并明确拒绝不可抓目标。

## 2026-08-31 鸟瞰点与自动视角规划调研

### 核心结论

鸟瞰点不应在每次任务中由人重新设定。更准确的概念是“观察位姿”，而不是必须位于目标正上方的鸟瞰点。

系统中的职责划分应为：

- 人或系统设计者离线定义相机允许活动的安全区域、与目标的距离范围、关节限制和禁止碰撞区域；
- 机械臂控制器判断候选位姿是否可达，并生成无碰撞路径；
- 视角规划器在线评价候选位姿，自动选择信息更多、遮挡更少且运动代价可接受的下一观察位姿。

常见的视角评分可以抽象为：

`视角效用 = 新信息量 + 目标可见度 + 深度质量 - 运动距离 - 碰撞风险 - 不可达惩罚`

### 三个实现层级

#### Level 0：单个固定观察位姿

- 工程师只在首次部署和标定时设置一次，并保存对应关节角或末端位姿。
- 每次抓取后程序自动返回该位姿，不需要人工重新设置。
- 优点是简单可靠；缺点是对停车位置变化和遮挡适应性差。

#### Level 1：有限候选观察位姿

- 离线保存约 3～5 个安全视角，例如中间、左侧、右侧、偏上和近距离观察位姿。
- 运行时依次或按评分选择候选位姿。
- 每到一个视角，计算苹果数量、检测置信度、深度有效率和运动代价。
- 选择评分最高且可达的视角进行抓取，信息不足时切换到下一个视角。
- 不需要深度强化学习，最适合当前项目。

#### Level 2：Next-Best-View 自动规划

- 系统根据 RGB-D 点云构建局部三维地图。
- 围绕已发现苹果或未探索区域自动生成候选相机位姿。
- 预测每个候选视角能获得的新信息，过滤不可达和可能碰撞的位姿。
- 自动执行效用最高的视角，并在获得新观测后重新规划。
- 适合严重遮挡和复杂植株，但需要三维建图、跨视角数据关联和运动规划。

### 当前项目的推荐方案

先实施 Level 1，而不是直接实现完整 NBV：

1. 将现有鸟瞰点保存为 `view_center`，只标定一次。
2. 在机械臂安全工作空间内增加 `view_left`、`view_right` 和可选的 `view_high`。
3. 每个视角连续采集多帧，为每个候选苹果计算检测置信度、深度有效率和坐标抖动。
4. 将不可达或路径碰撞的视角直接排除。
5. 如果当前视角已有可靠且可抓目标，立即停止观察并进入抓取；不要为了寻找理论最优视角继续移动。
6. 如果当前视角信息不足，选择预计信息增益更高且移动距离较短的下一个视角。
7. 抓取完成后先回到最近的安全观察位姿重新观察，不必强制回到唯一的 `view_center`。

第一版可以使用简单评分：

```text
score(view) =
  0.4 × 可见苹果数量
  + 0.3 × 平均深度有效率
  + 0.2 × 平均检测置信度
  - 0.1 × 归一化移动距离
```

这些权重只是待实验调节的初始值，不是研究结论。碰撞或不可达应作为硬约束直接排除，而不是只扣分。

### 相关研究

1. [Viewpoint Planning for Fruit Size and Position Estimation](https://www.hrl.uni-bonn.de/publications/2021/viewpoint-planning-for-fruit-size-and-position-estimation)（IROS 2021）：围绕已识别果实和未探索区域生成候选视角，通过预期信息增益评价候选点，并在机械臂 RGB-D 系统上验证。
2. [Graph-based View Motion Planning for Fruit Detection](https://arxiv.org/abs/2303.03048)（2023）：把可行观察位姿和位姿之间的路径组成图，同时考虑信息增益、机械臂运动约束和有限任务时间；提供了真实温室机械臂实验及开源实现。
3. [Semantics-Aware Next-best-view Planning for Efficient Search and Detection of Task-relevant Plant Parts](https://arxiv.org/abs/2306.09801)（2023/2024）：将检测、跨视角三维语义地图和下一最佳视角选择结合，真实温室实验中使用末端 RGB-D 相机主动寻找被遮挡的目标植物部位。
4. [NBV-SC: Next Best View Planning based on Shape Completion for Fruit Mapping and Reconstruction](https://arxiv.org/abs/2209.15376)（2022）：根据果实尚未观察到的表面生成新视角，并同时过滤不可达视角、重复视角和高运动代价视角。
5. [roi_viewpoint_planner](https://github.com/Eruvae/roi_viewpoint_planner)：IROS 2021 相关开源 ROS 代码，可重点查看 ROI、遮挡和信息增益的候选视角评价方式。

### 研究边界

上述论文主要证明“让机器人主动改变观察位姿可以提升被遮挡目标的感知覆盖”，并不意味着论文算法可以原样用于当前苹果抓取系统。相机型号、机械臂自由度、植株结构、运动空间和实时性均不同。当前应先用有限候选视角验证收益，只有当它明显优于单一鸟瞰点时，再投入完整三维 NBV 规划。
