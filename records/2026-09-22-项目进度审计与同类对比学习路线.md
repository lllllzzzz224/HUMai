# 机械臂项目进度审计、同类实验对比与学习路线

审计日期：2026-09-22。范围为本工作区的 RM65、D435、苹果/橘子实验。本次只读核查已有代码、日志、照片及公开研究，未连接或操作真机，未重新运行历史实验。历史测试通过数引用存档，不代表本轮复测。

## 目标

整理实际进度，区分已实现、已观察到成功、尚未验收和未来设想；建立与同类研究公平比较的口径；明确项目负责人应独立掌握的知识和可以交给 AI 辅助的工作。

## 总体判断

当前是**已有桌面果实抓取入盆成功案例的工程原型，正在补充可靠性评估和静态障碍感知规划**。

不能据现有证据称为已经完成复杂果簇自主采摘、可靠无损采摘、稳定无人干预多果清台，或具有已验证的通用毫米级果心定位精度。尚未发现满足统一条件、保留全部失败和人工干预的完整基准。

“成功案例存在”和“系统稳定可靠”是两个不同里程碑。现有成果值得保留，但下一步最缺的是可靠的测量和验证，而不是再增加一个模型名称。

## 需要校正的旧结论

1. **“三果连续自主100%成功”应降为“经过多轮调试累计三果入盆”。** 第十四轮明确记录操作员将果实推近约3cm，且中间有物理失败。不能选出三次成功当成总体成功率；也不宜把调参期间所有试验混成一个固定版本成功率。
2. **程序PASS是动作链证据，不是持果证据。** 9/14已有三次日志PASS但现场失败的反例。9/22日志没有独立的持果、滑落或果实入盆传感判据；新主机文档报告物理成功，但本轮没有补做现场确认。应分别存execution_ok、fruit_lifted、fruit_retained、placed_in_basin、damage_checked。
3. **“所有控制点1mm以内”“全系统精度0.01mm”没有成立。** 9/22摘要自己列出PREGRASP 1.07mm；往返TCP回读差约0.01mm不能替代独立外部测量，也不是整套视觉定位精度。新主机文档的部分置信度、半径、状态文字与所附JSON不完全一致，应以原始字段及其采样时刻为准。
4. **“1.85—1.92秒转场、5.5倍提速”不能当作整轮效率。** 当前可复核成功轮日志首尾为47、62、53秒，9/22单轮为66秒。这些含不同等待、预检和返回条件，也不能直接求一个具有普遍意义的均值。先统一计时起止点再比较速度。
5. **球拟合残差不等于球心真值误差。** 9/8的9.45mm是A、B两算法中心差，不是A距真实球心的误差；1.59mm是点到拟合球面的残差，不是球心绝对定位精度。[9/8记录](2026-09-08-真机苹果遮挡对比实验.md)
6. **球拟合未证明在所有条件优于原方法。** 9/7卡尺记录左苹果半径30.25mm，A估计30.30mm、B估计32.10mm；至少这枚果实的半径指标上A更接近所测尺寸。它也不能反过来证明A的三维球心一定更准。[9/7记录](2026-09-07-真机视觉球拟合对照实验.md)
7. **不能删掉重遮挡漏检来报告系统性能。** 没有检测输入的样本不能计算几何定位误差，但仍应计入端到端检测/任务失败，或单列拒绝原因；不能仅因为算法失败就作废。
8. **垂直抓取是当前台面/夹爪的有效工程约束，不是普遍物理定律。** 现有证据不支持“任何超过5°倾斜必失败”或“某个半径内绝对成功”。可达性还受目标高度、姿态、关节限位和碰撞影响。
9. **静态障碍进度以较晚验证报告为准。** 9/21日报“尚未实现”是当时状态；后续交付包表明开发副本已实现并做plan-only验证。但9/22单果执行不能据此被解释为自动枝叶避障也已部署并验证。
10. **README的Eye-to-Hand名称与当前代码不一致。** 相机固定到Link6对应Eye-in-Hand；本次修正入口说明，但外参实际精度仍需测量。

### 我们的优势

- **有真实系统而不只是识别图片。** 相机、定位、规划、夹爪、转运和复位均有运行证据，可以对定位改进是否最终提升物理抓取做实验。
- **有可回查的失败材料。** 保存了抓空、滑落、远处目标不可达、二维补偿引入偏移等资料；这是设计研究问题的基础。
- **组件可拆分、可替换。** 现有软件结构支持分别研究视觉、几何、状态机和场景建模；对学生项目而言，维护成熟基础组件比同时重造控制栈更可行。这是工程判断，不是已测得的性能优势。
- **正在建立拒绝不可靠输入的边界。** 已有未知空间、同步证据、场景读回和plan-only设计，方向合理；尚不能把设计边界当作已完成的整机安全认证。

### 主要劣势

- **最严重的是评估可信度。** 当前成功率、物理确认、时延口径不统一，部分摘要与原始记录冲突。
- **绝对几何误差未收敛。** 已有约3.97cm的尺测与模型高度差记录，尚未找到系统性验收其闭合的证据；夹爪、支架和手眼外参误差会传播到抓取与避障。
- **缺少任务结果反馈。** 控制器到位与夹爪命令成功，不能告诉系统果实是否还在手中。
- **复杂环境能力仍不完整。** 实际枝叶通道、未知空间、细枝漏深度、目标运动和动态重新规划均未形成已验收闭环。
- **采摘与桌面搬运之间仍有物理差距。** 果梗脱离、接触力、果实/枝条损伤、日光深度质量和长期可靠性没有本项目充分实验。
- **尚不能证明论文创新。** YOLO、RGB-D、球拟合和MoveIt的集成本身不构成已证实的新方法；需要明确问题、基线、消融和独立测试。

## 哪些东西需要人自己掌握

这里的“必须人来学”指项目负责人必须具备判断和验收能力，不是宣称这些工作技术上永远不能自动化。AI能写代码、解释论文、画点云和整理结果，但不能用文本推断替代没有采集的物理证据。你也不必亲自精通所有机械、电气细节；专业事项可交由懂它的团队成员承担，但你应知道何时必须找人验收。

以下不是判断你目前不会，而是检查标准：能独立完成就跳过，不能完成就作为学习任务。

| 优先级 | 需要掌握的内容 | 当前项目中的具体问题 | 学到什么程度算够 |
|---|---|---|---|
| P0 | 实验设计、指标和证据判断 | PASS为何不是物理成功？三次成功为何不是100%？ | 自己定义分母、成功和损伤标准；保留失败/干预；独立写出一份不夸大的结果表 |
| P0 | 坐标系、单位、TF、TCP、手眼标定 | 毫米与米、角度与弧度、相机/基座、真实指尖是否一致 | 画出像素→相机→Link6→base_link→TCP链；判断变换方向；用独立实测检查多位置偏差 |
| P0 | 真实设备操作与接触几何 | 指尖撞桌、倾斜推果、开爪外轮廓、抓持滑落 | 能检查急停、净空、模型与实物差异；认识闭合位置命令不等于夹持力或持果；异常时停止并描述现象 |
| P1 | ROS 2、MoveIt及基本运动学 | 节点运行为何仍无TF？有IK为何仍可能碰撞？ | 看懂topic/action/TF/规划场景；区分FK、IK、路径与带时间的轨迹；解释规划成功的假设 |
| P1 | RGB-D与视觉评估 | 分割漏检、无效深度、部分球冠拟合、时序不同步 | 区分置信度、召回率、拟合残差、重复性和绝对精度；能解释一张掩膜/深度/点云失败图 |
| P1 | Python/NumPy与调试基本功 | AI生成的脚本能否审查？参数改动是否真的生效？ | 读懂数据流、数组形状、异常、日志、配置和测试；能追查输入到控制目标的转换及单位 |
| P1 | 闭环、状态机与成功感知 | 果实被推走后仍执行旧坐标；空爪也继续入盆 | 写出每阶段进入/退出/失败条件，能判断反馈是否真的观测到任务结果 |
| P2 | 文献对照、消融、统计不确定性 | 如何证明自己的方法有贡献？ | 在同数据/同硬件/同条件下比较A/B，报告样本数、误差分布、置信区间和失败类型 |
| P2 | 主动视觉与信息不足时的决策 | 当前视角看不清怎么办？ | 理解换视角的收益、移动代价和观察位安全条件；先做有限安全视角对照 |

最小数学范围：三维向量、旋转和平移、矩阵乘法与逆、均值/方差/误差分布，以及球拟合的几何意义。先会用并检查这些量，不必先推导完整机器人动力学或深度网络反向传播。

可以主要交给AI辅助：检索和初筛论文、编写数据转换/绘图脚本、生成测试框架、整理ROS启动配置、分析日志、计算统计量和撰写草稿。人需要确认输入真实、统计口径正确、代码行为符合意图、物理结果确实发生。

暂不优先：从零训练大模型、端到端VLA、强化学习、完整动力学控制器、复杂多视角策略网络。先解决已发现的几何/测量/反馈问题，再用失败分布决定是否需要这些工具。

## 待确认问题

1. 9/22新主机单轮的独立物理结果与果品类别：文档称橘子，日志沿用apple字段，命名不能作为类别证据；应补充当轮现场照片/录像或明确观察记录。
2. 新主机运行代码、参数和模型与Mac各开发副本的对应关系；本次没有远程核查或部署。
3. 当前实际指尖长度、张开最大包络、相机支架尺寸及手眼外参精度，旧高度差是否已经消除。
4. 是否存在尚未归档的固定版本重复试验或果园实验；本报告不把“未找到证据”写成“从未做过”。
5. 如果最终农田对象是栀子果，应单独确认目标、果径/形状/果梗与验收任务。本目录苹果/橘子数据不能直接证明栀子果采摘效果。

## 后续实验与学习产出

按产出推进，不承诺未经评估的固定学习天数。

1. **先做证据复盘。** 选一轮真实成功、一轮程序PASS但物理失败，手工填“识别—定位—到位—夹起—保留—入盆—损伤”表，明确什么证据支持每格。
2. **完成几何验收。** 静止测量夹爪/指尖/支架、核对TCP和坐标链；在多个已知位置比较估计与独立参考。所需误差上限按果径、开度、接近方向和夹持余量制定，不凭空统一承诺1mm。
3. **冻结一个版本做无遮挡基准。** 选择5个已验证安全位置，每个10次，保留全部尝试、失败和人工干预；复位初始状态、打散位置顺序，记录版本/参数/光照。50次是初步基准，不是工业可靠性证明；运动须按现场条件另行预检。
4. **统一测量指标。** 至少报告物理入盆率、无损合格率、检测/定位/规划/夹持失败数、人工干预次数，以及从本轮开始到返回SCAN的耗时；另列视觉、预检、运动子段。跨果品分别统计，不混成一个数字。
5. **做同数据定位A/B。** 保持分割输入相同，只切换中心估计方法；采用独立几何参考，并保留重遮挡漏检，评估误差与最终抓取结果的关系。
6. **再验证固定障碍。** 在几何验收后先用易测量的不透明刚性障碍，验证同帧目标/障碍坐标、场景覆盖和预抓取通道，再进入受控真机动作；不要直接用最复杂枝叶作为第一轮。
7. **最后推进研究问题。** 可以研究“部分遮挡下的定位质量判别与拒绝/重观察策略”：证明它是否降低抓空、滑落、碰撞风险，并报告拒绝率与耗时代价。这是候选方向，创新性需进一步检索与实验确认。

建议你最先独立回答的三个问题：这次凭什么算成功？果实坐标相对于谁？机器人报告到位时，凭什么知道真实指尖没有碰到未知物体？这些问题能说明白，后续使用AI写代码才有可控的基础。
