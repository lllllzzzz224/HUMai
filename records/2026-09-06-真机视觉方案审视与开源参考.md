# 真机视觉方案审视与开源参考

## 目标

仅针对真机主线：让视觉在约定的静态单苹果场景中输出可验证的目标几何信息，并对信息不足给出明确拒绝。后续再扩展轻度遮挡。以三维误差、可靠输出比例和耗时评估方案，不以模型版本或检测置信度代替抓取可用性。

本次为源码审阅与公开项目调研，日期 2026-09-06；未运行相机、未操作机械臂、未训练或部署模型。Ubuntu 当前实际启动参数仍需现场核对。备份源码保持原样。

## 已确定内容

### 本地实现

- [视觉主程序](../ubuntu-backups/snapshots/2026-09-05/hand_eye_calibration/apple_pick_v2/apple_center_localizer_v2.py)默认 2 Hz 推理，类别 ID 固定为 47，使用裁剪候选及整图回退。
- [模型路径](../ubuntu-backups/snapshots/2026-09-05/hand_eye_calibration/apple_pick_v2/project_paths.py)默认指向 `models/yolo11n-seg.pt`，支持环境变量覆盖。
- 已使用分割多边形、彩色/深度时间差检查、相机内参和观测时刻 TF；没有掩膜时回退矩形区域。
- 当前中心估计在掩膜中央区域取有效深度中位数，用检测框宽高估计半径，再沿观察射线从可见表面向后补一个半径。它是近似几何模型，不是由完整苹果点云拟合得到的真值。
- [采样检查](../ubuntu-backups/snapshots/2026-09-05/hand_eye_calibration/apple_pick_v2/fixed_scan_real_verify.py)采集多个坐标，检查各轴极差、置信度和半径；这能检查重复性，不能单独证明绝对准确性。
- 输出 PoseStamped 使用发布时刻，而坐标变换使用观测时刻；后续应保留原始采集时间，同时记录处理延迟，避免旧观测被解释为新观测。
- [当前配置](../ubuntu-backups/snapshots/2026-09-05/hand_eye_calibration/apple_pick_v2/single_apple_full_grasp.yaml)还启用了固定 SCAN 下拟合的 XY 经验校正。需要在独立点位测量其收益，不能认为它保证所有观察位姿准确。

### 从第一性原理得到的判断

1. 平行夹爪需要目标相对夹爪的几何关系和接近空间。对当前固定方向抓取，中心和有效尺寸是有用的近似；无需一开始估计苹果完整六自由度姿态。
2. RGB 帮助分辨哪些像素属于苹果，深度提供可见表面距离；被遮挡的中心是推断值，必须与直接观测分开。
3. 遮挡会改变可见区域和检测框，导致半径与中心估计偏移。此时提高检测置信度或更换更大的 YOLO 不能保证解决定位问题。
4. 视觉误差、手眼/TCP 标定误差和运动误差共同消耗夹爪容差，应分别测量。固定视角的低波动不等于低偏差。
5. 看不到的空间应保留为未知；苹果分割之外的背景不能全部丢弃，后续需要用于支撑面和接近空间判断。视觉给出几何证据，规划层结合机械臂和夹爪模型判断可达性及碰撞。

## 开源项目核对

以下“可借鉴”是本次工程判断，不代表在 RM65 上实测优于现有方案。

### 1. OSUrobotics/apple-harvest：优先研究苹果定位流程

- [项目](https://github.com/OSUrobotics/apple-harvest)提供 RGB-D 苹果定位、UR5e 采摘、视觉伺服和分阶段记录；开发环境为 ROS 2 Humble，和本项目 Jazzy/RM65 存在适配差异。
- 核对源码版本：`7ee995ab4fc7f6bac0dc44b9a2403fea3c2a3bc3`。
- [apple_prediction.py](https://github.com/OSUrobotics/apple-harvest/blob/7ee995ab4fc7f6bac0dc44b9a2403fea3c2a3bc3/harvest_vision/harvest_vision/apple_prediction.py)包含实时/离线模式、分割区域反投影与球拟合。
- [sphere_ransac.py](https://github.com/OSUrobotics/apple-harvest/blob/7ee995ab4fc7f6bac0dc44b9a2403fea3c2a3bc3/harvest_vision/harvest_vision/sphere_ransac.py)提供带半径范围的 RANSAC 球模型。实现会裁剪候选半径，不能直接把半径落在范围内当作模型正确；退化点集、拟合残差、内点比例和可见曲面覆盖仍需验证。
- 仓库目录列有苹果检测权重和 `best_segmentation.pt`；本次未下载运行这些权重，类别、来源和在本机上的效果仍待确认。
- [package.xml](https://github.com/OSUrobotics/apple-harvest/blob/7ee995ab4fc7f6bac0dc44b9a2403fea3c2a3bc3/harvest_vision/package.xml)许可字段仍为 `TODO: License declaration`，本次递归目录未见 LICENSE 文件。将其视为公开研究参考；直接复制或分发前需明确授权条款。

### 2. mgonzs13/yolo_ros：借鉴 ROS 2 感知接口

- [项目](https://github.com/mgonzs13/yolo_ros)列出 Jazzy 支持，提供检测、分割、跟踪和深度三维输出。
- 优先参考消息、参数、节点拆分及同步方式，而不是为了使用它重写已经可工作的控制流程。
- [三维节点](https://github.com/mgonzs13/yolo_ros/blob/main/yolo_ros/yolo_ros/detect_3d_node.py)输出通用三维框；不能将通用框中心直接当作遮挡苹果完整中心。默认参数需要按本机采集时序及误差要求重新验收。源码采用 GPL-3.0-or-later 声明。

### 3. Open3D：优先用于离线点云处理

- [项目](https://github.com/isl-org/Open3D)和[官方离群点教程](https://www.open3d.org/docs/release/tutorial/geometry/pointcloud_outlier_removal.html)可用于 RGB-D 点云构建、可视化、统计/半径离群点过滤。
- [点云教程](https://www.open3d.org/docs/release/tutorial/geometry/pointcloud.html)提供聚类、平面分割等示例。
- 借鉴用途：把苹果掩膜内点云和背景点云分别显示，检查是否混入叶片/桌面。Open3D 是处理工具，不是自动解决苹果中心的模型；点云聚类中心也不等于完整果实中心。

### 4. facebookresearch/sam2：分割对照和辅助标注候选

- [项目](https://github.com/facebookresearch/sam2)提供提示式图像/视频分割、模型和示例。
- 可在已有 YOLO 框或人工提示下生成候选掩膜，人工校正后辅助标注，并与 YOLO 掩膜比较。
- 本阶段不默认接入真机主循环；它不直接提供米制深度、手眼变换或安全抓取判断，运行成本和收益须在 Ubuntu 上测量。

### 5. Eruvae/roi_viewpoint_planner：留到主动视觉阶段

- [项目](https://github.com/Eruvae/roi_viewpoint_planner)提供围绕兴趣区域的观察位姿采样与效用评价，依赖扩展 OctoMap 及配套包。
- README 使用 `rosrun` 和 ROS 1 相关组件，不是 Jazzy 即插即用方案。
- 借鉴“根据可见信息选择观察位”的方法；现阶段先验证少数固定观察位，避免直接移植完整规划器。

### 不作为本轮主线：Apple-Tracking

[仓库](https://github.com/rishabhpahuja/Apple-Tracking)可以参考三维目标关联；但 README 自报速度仅 0.12–0.15 FPS，并将实例分割改善和球拟合列为后续工作。其双目视差链也与我们已有 RGB-D 输入不同，不适合作为即用替代品。

## 建议方案（未实施）

```text
保存原始 RGB、对齐深度、内参、观测时刻 TF
    ↓
现有 YOLO 分割：输出可见苹果区域
    ↓
掩膜边缘处理 + 无效深度剔除 + 必要的深度聚类
    ↓
苹果可见表面点云
    ↓
对照：当前中心估计 / 有半径约束与质量检查的球拟合
    ↓
多帧同目标一致性 + 定位质量判定
    ↓
中心、尺寸、观测时间、坐标系、质量指标、拒绝原因
```

球拟合只有在可见曲面信息足够时才可能有收益。小片可见表面可能支持多种不同球心，不应仅凭低残差接受；拟合结果需要可见覆盖、半径合理性、重采样稳定性及独立实测误差共同支持。第一轮无需引入完整 SLAM、场景重建或端到端策略。

## 待确认问题

- Ubuntu 实际模型路径、类别表、相机型号、深度编码/单位、分辨率、算力和耗时。
- 苹果真实尺寸、夹爪允许误差、TCP 定义及手眼误差各是多少。
- 现有日志是否有足够原始 RGB-D、内参和观测时刻 TF 支持公平离线回放。
- 现有分割失败与中心估计失败各占多少；换模型的主要收益是否真在识别层。
- 外部苹果分割权重是否可用、许可与数据来源是否清楚、是否有完整配套评测。

## 后续实验

1. 接通 Ubuntu 后先只读核对环境，再在无抓取执行的条件下采集同步数据。
2. 初始采样建议 100–300 组 RGB-D，覆盖无遮挡、负样本、距离/光照变化和轻度遮挡；这是诊断批次，不宣称足以证明泛化性能。保留短序列测波动。
3. 按苹果个体和采集场次划分开发集及保留测试集，避免相邻帧分入两边。
4. 比较 A：当前完整视觉算法；B：相同 YOLO，改进深度/中心算法。只有分割成为瓶颈时，增加 C：替换或微调分割模型，其他环节保持一致。
5. 记录检测/分割错误、中心实测误差、重复性、正确拒绝、错误接受、可靠输出比例和端到端延迟。拟合残差不是实际定位误差。
6. 用已知尺寸球或可重复测量工装建立几何参考；再用真实苹果检查形状偏离球体的影响。换视角比较是内部一致性测试，不替代绝对真值测量。
7. 三维误差门槛根据夹爪容差和其他环节误差分配；不直接沿用示例项目的置信度、同步窗口、半径或毫米阈值。
8. 离线通过后再验证末端预抓取到位，最后进入抓取和无损验收。所有开发在独立工作目录进行，不改备份快照。
