## 已确定内容

### 1. 真实落地技术栈全景还原（当前真机闭环事实）

当前真机在密集的树枝与仿真树叶遮挡下，实现连续 100% 成功抓取并入盆（见实测记录 [2026-09-23-叶片深度剥离与纯枝干碰撞解耦实验.md](2026-09-23-叶片深度剥离与纯枝干碰撞解耦实验.md)），其底层技术体系完全由**本地毫秒级端侧视觉与经典几何力控算法**构成，**未接入任何外部或本地 LLM/VLM 大模型**。

#### 各层核心技术指标与物理事实：
1. **2D 目标检测（本地 YOLOv8）**：
   - 运行在本地边缘端计算单元上，单帧推理耗时仅 12~15 ms；
   - 作用仅限于圈定可能存在果实的 2D ROI 区域，不负责生成最终抓取位姿。
2. **叶片剥离与去噪（色度学第一性原理 ExG）**：
   - 利用植物叶绿素对光谱绿波段的高反射率以及红、蓝波段的高吸收率，采用超绿指数：
     $$\text{ExG} = 2G - R - B > 10$$
   - 直接在 RGB-D 点云的反投影三维矩阵上做逐点向量化布尔掩码过滤。全场景 246,782 个点中，77.9%（192,200 个点）的绿色叶片点在 2ms 内被纯数学运算彻底剥离，无需经过任何神经网络。
3. **果实 3D 定位（凸面约束与物理先验 RANSAC 球拟合）**：
   - **破解深度飞点**：RealSense D435 在叶片（深度 0.447m）与果面（深度 0.497m）的交界边缘存在 10~15 像素的立体匹配拉丝（Depth Smearing）；
   - **凸面约束**：施加物理约束 $C_z > Z_{\text{surface}}$，杜绝拟合出面向相机的凹面“碗状”伪球；
   - **物理先验**：限定拟合球半径 $R \in [28, 42]\text{ mm}$，有效抵抗局部遮挡导致的几何退化；
   - 连续 5 帧球心 Z 轴跳动跨度从 **52.0 mm 压缩至 7.52 mm**（降幅 85.5%），定位 RMSE 仅 $1.22 \sim 1.40\text{ mm}$。
4. **规划层体素解耦（MoveIt 2 场景）**：
   - 原始点云生成的 2,442 个 OctoMap 体素中，剔除软叶与果体后，仅剩 447 个纯木质硬枝与支撑面体素（刚性干涉点骤降 81.7%）；
   - 预抓取位干涉点从 114 个降至 12~17 个；使原本因叶片遮挡而报 `NO_IK` 的大角度（右倾 +15°、偏航 ±30°）姿态全部变为 `IK_OK`，机械臂获得充裕的运动学求解自由度。
5. **物理控制层（穿透下潜与强制包络 Forced Enveloping）**：
   - 夹爪开度扩容至 98.0mm，穿透叶层下潜至果实赤道（`grasp_above_apple_m: 0.020m`）；
   - 平爪持续驱动直至电机堵转锁死（行程 0.0mm）；
   - **接触力学机理**：超薄质轻的植物软叶在两指平爪与双曲率果皮之间充当了**柔性缓冲摩擦介质（Compliant Friction Interface）**，消除了点接触应力集中，增大了微观有效接触面积，不仅未滑脱，反而牢固锁定果实入盆。
   - **真实物理证据**：
     - 日志：[records/evidence/single_apple_grasp_20260923_131547.json](evidence/single_apple_grasp_20260923_131547.json) 与 [records/evidence/single_apple_grasp_20260923_133100.json](evidence/single_apple_grasp_20260923_133100.json)；
     - 现场实拍：[records/assets/after_grasp_occluded.jpg](assets/after_grasp_occluded.jpg)（果实连带软叶稳定落入料盆中央）。

### 2. 第一性原理剖析：为什么当前工程闭环坚决不采用纯 LLM/VLM？

从工程落地与物理第一性原理审视，“把照片交给大模型处理，让其识别叶子并替换为可穿过的遮挡”在当前的真机控制回路中存在四大致命障碍：

#### (1) 控制回路时延与动态响应（Latency & Real-time Control）
- **机械臂控制的时钟本质**：机械臂的轨迹插补与安全门禁要求毫秒级响应（典型控制周期在 20ms ~ 100ms，即 10Hz ~ 50Hz）。如果要在机械臂运动过程中检测动态遮挡或更新避障走廊，感知处理必须压缩在几十毫秒内。
- **对比数据**：
  - 云端 VLM API（如 GPT-4o, Claude 3.5 Sonnet）：网络往返 + 视觉编码 + 自回归生成，延时通常在 **1,500 ms ~ 4,000 ms**（1.5~4 秒）；
  - 本地边缘部署的 7B~8B 视觉大模型（如 LLaVA-NeXT, InternVL2）：在 Jetson Orin 上量化推理单帧也需要 **800 ms ~ 2,000 ms**；
  - 本地轻量化算法：ExG 矩阵布尔运算 **< 2 ms**，YOLOv8 **< 15 ms**，RANSAC 拟合 **< 10 ms**，全链路耗时 **< 30 ms**。
- **工程结论**：秒级延迟的大模型绝对无法接入机械臂的高频运动学控制与安全门禁闭环，否则极易造成由于感知滞后引发的真机撞击与超调。

#### (2) 缺乏真实度量几何能力（Metric 3D Geometry Deficit）
- **语义空间与欧氏空间的本质割裂**：
  - LLM/VLM 是**语义概率模型**，它理解的是抽象的“概念”（“这是一片树叶”、“橘子被遮挡了”），其输出形式为文本、像素级 Bounding Box 或 2D 热力图；
  - 机械臂运动学求解器（KDL / TRAC-IK）需要的是严格的**欧几里得度量几何（Metric Euclidean Geometry）**：包含绝对物理尺度的毫米级坐标（如 $X=0.2712\text{ m}, Y=-0.3039\text{ m}, Z=-0.0566\text{ m}$）、表面法向量、曲率半径以及三维障碍物刚性包围体。
- **工程结论**：大模型无法仅凭一张 2D RGB 照片凭空推断出具备真实毫米精度的 3D 深度分布与相机外参位姿。若缺少直接的深度传感器与解析几何运算，大模型生成的“遮挡位置”根本无法直接喂给 MoveIt 2 进行无碰撞逆解。

#### (3) 工业级确定性 vs 大模型幻觉（Determinism vs Hallucination）
- **物理系统的不可逆破坏性**：软件崩溃可以抛出 Exception，但重达数公斤的高扭矩金属机械臂一旦轨迹算错或障碍物判断失误，就会撞毁 RealSense 相机、折断末端舵机或挤碎工件；
- **确定性安全链条**：当前落地的 ExG + 凸面约束 RANSAC 算法具备 100% 的数学确定性与可追溯性。配合系统安全门禁（`AppleStabilityGate`），在遇到退化数据时能立即给出明确的物理拒绝码（如 `Cz <= Z_surface` 或 `Radius out of bounds`）；
- **大模型的不可靠性**：大模型基于概率采样，存在不可避免的幻觉（Hallucination）。即使提示词（Prompt）完全一致，也可能在某一帧中漏判关键木质枝条，或将果皮反光误认为障碍物，给物理执行带来无法接受的安全隐患。

#### (4) 端侧算力开销与功耗成本（Edge Compute & Power Envelope）
- 田间采摘移动底盘或紧凑型边缘工作站通常由电池供电，算力平台受限于功耗（如 Jetson Orin Nano 仅 15W，Orin NX 仅 25~40W）；
- 运行完整 VLM 需要消耗 8GB ~ 16GB 显存，这会与 ROS 2 底层节点、RealSense 驱动、MoveIt 2 场景规划器发生严重的显存与算力争抢；
- 相比之下，YOLOv8 + ExG 矩阵运算仅需百兆显存，CPU 占用率低于 5%，能以极低功耗维持极高稳定性。

### 3. LLM/VLM 在具身智能采摘中的正确定位：分层智能架构

具身智能绝不等于“用大模型端到端控制机械臂电机”。合理的机器人系统架构必须遵循**分层智能（Hierarchical Embodied Architecture）**，使大模型与传统几何控制各司其职：

```
┌────────────────────────────────────────────────────────────────────────┐
│                   顶层：认知与常识规划层 (Cognitive Layer)              │
│               [LLM / VLM: 异步低频决策 ~0.2Hz - 0.5Hz]                 │
│                                                                        │
│  - 农艺常识理解 (如: 品种识别、果实成熟度、病虫害判别、果梗木质化程度)    │
│  - 长程任务规划与高层策略分派 (如: "果簇密集, 先拨开上方浮叶再采摘")      │
│  - 异常故障诊断与自然语言交互 (如: "连续3次抓取滑脱, 建议扩大夹爪开度")    │
└──────────────────────────────────┬─────────────────────────────────────┘
                                   │ 高层离散指令 / 语义掩码 (Semantic Mask)
                                   ▼
┌────────────────────────────────────────────────────────────────────────┐
│                   中层：语义度量与感知层 (Metric Perception)            │
│               [SAM-2 / YOLOv8 / RGB-D 点云 / ExG / RANSAC]             │
│                                                                        │
│  - 2D 目标检测与实例分割 (获得橘子与障碍物像素轮廓)                       │
│  - 点云反投影与可渗透度标注 (Affordance: 绿叶=软介质, 木枝=刚性障碍)      │
│  - 几何拟合与状态估计 (凸面约束球拟合, 毫米级三维坐标 Cz, R)             │
└──────────────────────────────────┬─────────────────────────────────────┘
                                   │ 连续位姿 (PoseStamped) / 碰撞体素网格
                                   ▼
┌────────────────────────────────────────────────────────────────────────┐
│                   底层：物理几何与运动控制层 (Physical Control)        │
│               [ROS 2 / MoveIt 2 / 电流力控 / 夹爪驱动 ~50Hz]            │
│                                                                        │
│  - 运动学逆解 (IK Solver: TRAC-IK / KDL)                               │
│  - 笛卡尔空间轨迹规划与动态避障 (OMPL / MoveIt 2)                       │
│  - 接触力学与力矩控制 (穿透下潜, 堵转自锁, 柔性包络)                     │
└────────────────────────────────────────────────────────────────────────┘
```

#### 未来引入 VLM 的最具可行性切入点：Affordance / Soft-masking（可渗透软障碍物分割）
若未来在系统中引入大模型或通用视觉分割模型（如 SAM-2、FastSAM、Grounding-DINO），其最合理的工程定位是：**语义可渗透性（Affordance）的软掩码标注者**。
1. **语义赋予**：VLM 不去解算三维坐标，而是输出高精度的 2D 语义分割掩膜，明确区分“柔性易形变叶片（Flexible Leaves）”与“刚性木质硬枝（Rigid Branches）”；
2. **代价图投射（Costmap Mapping）**：将该语义掩码投射到 3D 深度点云，通知 MoveIt 2 / OctoMap 规划器：
   - 将对应“叶片”的体素属性标记为 `Soft_Medium`（碰撞权重 Cost = 0，允许直接穿透）；
   - 将对应“树枝”的体素属性标记为 `Hard_Obstacle`（碰撞权重 Cost = $\infty$，强制严格避障）；
3. **闭环保持**：底层的空间度量、凸面球拟合、轨迹生成与力矩抱死，依然完全交由底层的 ROS 2 与 MoveIt 2 确定性算法执行。

## 待确认问题

1. **边缘端大模型轻量化可行性**：
   - 若在本地 Jetson Orin 平台上部署 FastSAM 或 MobileSAM 提取软介质掩码，其实际显存占用（是否超过 3GB）与单帧推理耗时（能否压至 200ms 以内）仍需真机环境测试核对。
2. **色度学 ExG 算法的光照适应边界**：
   - 当前超绿指数（ExG: $2G - R - B > 10$）在室内工况下表现极佳；但在户外强阳光直射引起叶片泛白、或阴雨天光照较暗时，固定阈值 10 是否会出现漏滤或误滤，是否需要升级为自适应超绿阈值算法。
3. **农艺操作下的枝条机械损伤评估**：
   - 当前“带叶连抓”策略利用了软叶的摩擦缓冲，但在真实果树环境下，叶柄抗拉极限是多少，强行带叶起吊是否会造成母枝撕裂伤，需结合农艺规范确认。
