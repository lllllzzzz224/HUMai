# 2026-09-19 机械臂真机实验与 Agent 协作规范

## 目标

建立软件工程 Agent 与人类开发者在真实机械臂作业环境下的工作准则与安全边界，规范代码变更、现场验证、异常处置和多 Agent 协同流程，防止因盲目下发运动指令导致设备撞击或数据丢失。

## 已确定内容

1. **沟通与表达原则**：
   - 默认使用中文交流，坚持“结论先行”，先给出最终结论或下一步动作，再展开技术原因与依据。
   - 严禁模糊推测冒充实测事实：明确区分“事实”（有文件/日志/图片证据）、“推测”（基于代码或理论推断）和“建议”（后续方案）。

2. **真机实验安全红线（最高优先级）**：
   - **文档与代码请求不自动包含运动授权**：用户要求“编写文档”“排查 bug”或“重构代码”时，严禁自行向实体机械臂或夹爪发送动作指令。
   - **禁止擅自追加动作**：不得因预抓取（Pre-grasp）对齐成功就擅自追加下降、闭爪、提拉或回程指令；每一步涉及物理执行的操作必须处于用户明确授权的批次与范围内。
   - **严谨界定四级判定标准**：
     1. `代码运行成功`（程序退出码 0）
     2. `规划通过`（MoveIt OMPL 轨迹求解成功）
     3. `动作完成`（机械臂控制器执行反馈完成）
     4. `实物任务成功`（物理果实确实被稳定采摘并置入盆中）
     四者严禁混淆，不能把程序 PASS 或轨迹规划成功等同于物理抓取成功。

3. **多 Agent 协作约束**：
   - 涉及物理机械臂时，**全局同一时刻只允许一个执行方（Lead Agent）持有下发控制指令的权限**，其余 Agent 仅能进行只读分析、日志审计与文档整理。
   - 子 Agent 汇报的完成状态必须由主 Agent 交叉比对数据/传感器证据后方可采纳。

## 待确认问题

1. 远程终端与主控端并发操作时的互斥锁（Hardware Mutex Lock）仍依赖人工约定，未来可考虑在 ROS 节点层实现话题与动作服务器的硬件独占令牌机制。

## 后续实验

1. 将本协作规范作为工程团队与 AI 助手操作物理机械臂的核心指导准则长期执行。
2. 依据本规范推进静态障碍物离线建模，全流程保持 `executable=false` 状态。
